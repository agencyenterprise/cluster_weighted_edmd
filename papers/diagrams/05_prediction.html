Input
$x_t$
query state
→
Assign cluster
$k^* = \underset{k}{\arg\max}\; \pi_k \!\cdot\! \mathcal{N}(x_t;\, c_k, \Sigma_k)$
proximity only (no $f$ available)
→
Apply $L_{k^*}$
$\hat{x}_{t+1} = L_{k^*}(x_t)$

→
Output
$\hat{x}_{t+1}$
predicted next state
Key design choice: proximity-only assignment at test time
Training: $r_{ik}$ uses both proximity AND residual (we know $f(x_i)$)
Test time: $k^*$ uses proximity only (we don't know $f(x_t)$ — that's what we're predicting)
This is a mild distribution shift between train and test cluster assignment. It works because the EM-trained clusters already align with dynamics quality: regions where $L_k$ fits well are also the regions where the proximity factor places points.
Standard GMM (no dynamics)
Assign $k^*$ by proximity → apply global $f$ model
Cluster boundaries follow density contours
Our method (CWM)
Assign $k^*$ by proximity → apply local $L_{k^*}$
Cluster boundaries follow linearizability contours
